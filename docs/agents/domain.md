# Domain docs

This is a single-context repository.

## Before exploring

Read these resources when they exist:

- `CONTEXT.md` at the repository root.
- ADRs under `docs/adr/` that affect the area being changed.

Proceed silently when either resource is absent. Domain-modeling work creates
them lazily when terminology or architectural decisions need to be recorded.

## Use the glossary vocabulary

Use terms as defined in `CONTEXT.md` in issue titles, proposals, hypotheses,
tests, and code. Do not drift to synonyms that the glossary rejects.

If a necessary concept is missing, reconsider whether new terminology is
needed or record the gap for domain modeling.

## Flag ADR conflicts

Surface a conflict with an existing ADR explicitly rather than silently
overriding the decision.
